# P11: P10-executable G/U/E and Scene-State Forcing

Status: design contract for falsification pilots. It is not a promotion claim.

## 1. Frozen executor boundary

P10 is the frozen renderer

```text
ScenePlan S --P10 DiT, render seed e--> FOA waveform A
```

P11 never replaces this mapping and does not generate a waveform latent. It
must emit a ScenePlan, or an atomic patch that deterministically produces one.
Every emitted plan is validated against the canonical P10 checkpoint and its
current capability envelope before rendering:

- 44.1 kHz, four-channel FOA;
- at most 648 VAE frames (about 15.05 seconds);
- one to four sources, and at most one formal speech source;
- music, sound, and speech source kinds;
- one activity interval per source;
- static or linear motion only;
- the frozen semantic-caption v2 transcript surface;
- gain fixed at 0 dB in the P11/P10 intersection;
- no word timing, keyframed motion, or waveform-local preservation claim.

There are two independent sources of variation:

1. P11 changes `S`, which changes scene content, timing, geometry, or room.
2. P10 changes `e`, which changes the acoustic realization of the same scene.

Controllability tests hold `e` fixed while changing `S`. Renderer-diversity
tests hold `S` fixed while changing `e`. The two must never be conflated.

## 2. Three non-symmetric task contracts

### Generation: intent compiler

```text
user intent x -> complete executable ScenePlan S -> P10(S, e) -> FOA A
```

P11 completes fields that the prompt does not specify, but evaluation only
compares explicitly constrained fields to the prompt. Unspecified fields are
judged by P10 validity, prior plausibility, and diversity rather than equality
to one arbitrary synthetic target. Exact prompts may still use full-plan
accuracy.

The continuous target for G is the complete P10-executable state `c(S)`.
Semantic descriptions and the exact speech transcript remain discrete.

### Understanding: inverse scene inference

```text
FOA A -> evidence encoder -> posterior q(S | A) -> MAP plan S_hat
                                           |
                                           +-> P10(S_hat, e') for cycle audit
```

Understanding recovers a ScenePlan that explains the FOA. It is not a literal
inverse of one stochastic P10 render: different seeds and sometimes different
plans can be acoustically equivalent. The user-facing result is one canonical
MAP plan plus confidence; training and evaluation treat source order as
permutation invariant.

Synthetic supervision uses multiple P10 seeds per ScenePlan so the inverse
model learns scene state rather than renderer noise. A cycle audit compares
semantic, activity, DOA/trajectory, distance-band, and room evidence between
the input and a re-render; it does not require waveform equality. Duration is
observed from valid FOA frames, not hallucinated by the planner.

General audio question answering is a possible consumer of `S_hat`, but it is
not part of this core P10-aligned Understanding contract.

### Editing: transactional ScenePlan transition

```text
current plan S + instruction i -> atomic patch DeltaS -> validated S'
                                                    -> P10(S', same e) -> A'
```

The canonical edit input is the current canonical ScenePlan, not a waveform.
The patch changes only fields named by the instruction; all other fields are
preserved exactly. Multi-turn training stores the hash-chained sequence
`S0, DeltaS1, S1, ..., DeltaSk, Sk`.

If only an external FOA is available, the product path is explicitly a
cascade:

```text
A -> Understanding -> S_hat -> Editing -> S_hat' -> P10 -> A'
```

This is scene-level re-synthesis editing. It must not claim preservation of
the unedited waveform. For audio generated by this system, retaining the
original ScenePlan and P10 seed permits a much cleaner fixed-seed edit audit.

## 3. P10-executable Scene-State Forcing

Let `c(S)` be the frozen continuous executable core compiled from a ScenePlan.
The discrete planner still emits canonical ScenePlan or patch tokens.

- G: flow-match a noisy target `c(S)` conditioned on text.
- U: flow-match a noisy target `c(S)` conditioned on FOA temporal/spatial and
  semantic evidence.
- E: flow-match a noisy executable delta `c(S') - c(S)` conditioned on clean
  `c(S)` and the instruction, with a hard ownership/locality mask.

The deployment-aligned canonical E arm uses clean current state and noisy
target delta. Gaussian corruption of current state is not the default because
the stored ScenePlan is exact at inference. Independently noised history is a
robustness ablation for U-to-E cascades or long rollouts. A stronger later
robustness treatment uses model-produced, canonicalized previous plans rather
than arbitrary Gaussian history corruption.

For every task, the state consumed by the discrete decoder is obtained by the
same target-free ODE solve used at inference. A flow bridge containing the
clean target is loss-only and may never reach the decoder.

## 3.1 Strict Transfusion-CoT realization

The small standalone SceneThought transformer is a useful connector/flow
baseline, but it is not by itself a strict Transfusion model. The strict arm
uses one shared Qwen transformer to process a mixed sequence:

```text
discrete task/prompt tokens
continuous FOA evidence tokens when U is active
continuous noised executable Scene-State thought span
discrete ScenePlan or atomic-patch output tokens
```

At continuous thought positions, a velocity head receives the shared Qwen
hidden state and is trained with flow matching. At discrete output positions,
the shared hidden state is trained with next-token cross entropy. Modality,
slot-role, task, round, and flow-time embeddings identify each span.

The P10-aligned mixed sequences are:

```text
G: <G> prompt <STATE_R1> z </STATE_R1> <PLAN> S
U: <U> FOA/semantic/lexical evidence <STATE_R1> z </STATE_R1> <PLAN> S_hat
E: <E> S instruction <DELTA_R1> dz </DELTA_R1> <PATCH> DeltaS
```

An optional second span refines inventory into execution state:

```text
<STATE_R1: inventory> -> <STATE_R2: P10 execution>
```

R2 is retained only if it improves difficult multi-source/spatial cases. A
single target-free executable state is still a valid continuous reasoning
step; simply encoding the target ScenePlan and exposing it to the decoder is
not.

The current `core40` captures P10 geometry, timing, source kind, room, and
presence flags, but not the content of open-vocabulary source semantics. The
strict arm therefore appends a frozen source-semantic target to each active
source slot (text embedding for G/E and aligned audio/text embedding for U).
Exact speech words remain discrete lexical state. U requires pinned ASR/lexical
evidence if exact transcript reconstruction remains in the ScenePlan contract;
a global CLAP vector alone is not sufficient evidence for that field.

The plan-token decoder may consume only a thought obtained from target-free
inference. Random flow bridges containing the clean target train the velocity
field but never condition token CE. A practical shared-backbone implementation
alternates or packs a flow pass with a target-free thought/decoder pass, rather
than performing an expensive full Qwen ODE solve for every CE update.

For multi-turn Editing, independent noise levels may be assigned to successive
continuous state/delta spans, which is the Diffusion-Forcing component. It is
not asserted for single-turn G/U, and it remains an ablation unless it improves
model-produced-history or U-to-E cascade robustness.

## 4. Required losses

```text
L = L_discrete
  + lambda_flow * L_executable_flow
  + lambda_core * L_core_endpoint
  + lambda_bind * L_slot_field_ownership
  + lambda_local * L_edit_locality
```

`L_discrete` covers ScenePlan or atomic-patch tokens. `L_executable_flow` and
`L_core_endpoint` cover only fields P10 can execute. `L_slot_field_ownership`
requires source-owned thought interventions to affect the corresponding
ScenePlan fields. `L_edit_locality` includes exact zeros outside the edit mask.

Full P10 rendering is too expensive for every optimizer step. Exact ScenePlan
validation and frozen P10-conditioning compilation run as the cheap training
contract; frozen P10 renders are used in held-out closed-loop evaluation.

## 5. Evaluation contracts

Generation:

- parse, canonical round trip, and P10 capability validity;
- explicit prompt-constraint satisfaction;
- exact full-plan score only for exact prompts;
- fixed-seed plan intervention and multi-seed renderer-diversity panels.

Understanding:

- permutation-invariant source count/kind/semantic matching;
- transcript accuracy for speech;
- activity IoU and onset/offset error;
- DOA/trajectory/distance and room metrics;
- confidence calibration and P10 feature-cycle consistency;
- separate synthetic and real-FOA panels.

Editing:

- patch parse and exact application;
- requested-field success and unchanged-field exact preservation;
- multi-turn state validity and no error accumulation;
- fixed-seed P10 causal audio delta in the requested semantic/spatial field;
- separate exact-plan and U-to-E cascade panels.

All promotion tables report G, U, and non-no-op E separately. A macro score may
summarize them but cannot hide a failed task, failed parser, failed
intervention, or P10 capability violation.

## 6. Minimal falsification matrix

1. Discrete ScenePlan planner.
2. Continuous connector without flow.
3. Executable-state flow with clean E history (canonical).
4. Shared-timestep noisy-history forcing (robustness ablation).
5. Independent-timestep noisy-history forcing (robustness ablation).

The forcing claim survives only if the canonical arm improves held-out G/U/E,
passes learned slot interventions, and produces the expected fixed-seed P10
audio changes. Independent noisy history must additionally beat clean history
on U-to-E or multi-turn corruption tests; otherwise it is removed.
